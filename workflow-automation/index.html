    03The problem

    It’s not the work. It’s the work between the work.

    The job itself usually goes fine. What quietly eats the week is everything around it: retyping the same customer into three places, remembering which quote never got an answer, invoicing the job that finished last Tuesday, chasing the invoice from six weeks ago, and assembling the numbers into something you can act on.

    Every one of those is a handoff. Every handoff depends on somebody remembering. That’s the leak.

    Automation done right doesn’t replace your judgment — it replaces the remembering. The system watches the handoffs, does the drafting and the arithmetic, and brings you a short list of decisions instead of a long list of chores.

    The system decides who and what tone. You decide whether.

    Here’s the shape every one of my builds takes.

    04How every build is wired

    Five layers. The same five, every time.

    Anyone can connect two apps together. What makes one of these hold up on week forty is the shape it was built in. Every system I build has the same five layers, and each one has a rule I don’t break — including on the days it would be faster to.

    01The sensorIt watches. It never touches.

    Something has to notice. A schedule that wakes up Monday morning, a form submission, a new row in a sheet, an email landing in an inbox. The rule: the sensor is read-only. It looks at your data and never writes back to it. If you unplugged my system tomorrow, your spreadsheet would be exactly the file you’d have had anyway.

    02The mathThe AI never does arithmetic.

    Every total, every days-overdue count, every “this is up 12% from last month” is computed by an ordinary formula in your own sheet, before any AI is involved. The rule: the AI never does arithmetic. This isn’t caution for its own sake — during an early build the model added up a column itself and got it wrong. The fix wasn’t a better prompt. It was removing the model’s opportunity to do arithmetic at all. Every number the AI writes is a number that already existed in a cell you can click on.

    03The brainWords only. Every figure traces to a cell.

    Now the AI gets the verified numbers and does the thing it is genuinely excellent at: turning them into three paragraphs a human would actually read, and drafting the follow-up emails in a tone that fits the situation. The rule: narrative only. Every figure in what it writes traces back to a cell.

    04The gateNothing sends itself. Ever.

    Anything that would leave your business with your name on it stops here and waits. The drafts stack up. You read them, you delete the one that’s wrong, you press send on the rest. The rule: no exceptions — not for “obvious” ones, not for the third reminder, not at 2am. This is the layer everyone else skips, and it’s the reason you can hand this thing your customer list without lying awake. You are the only one allowed to press send.

    I publish my own bugs.

Each of the four left a permanent check behind.

    Isolation was proven, not assumed.

    When a loop setting looked like it might collapse a multi-client run into one send, I stopped reading documentation and ran it live: two sends, six seconds apart, distinct narratives per row, in the execution record. Now it’s a fact I read off a log instead of a belief I took from a doc.

    An automated quality gate blocks my own pushes.

    A script scores every workbook and every page for defects and runs on a git pre-push hook — if the score goes up, the push is refused. On the last recorded run the score was zero.

    Everything rebuilds identically.

    Twelve sample workbooks, each generated by its own Python script rather than assembled by hand, all reading brand colours from a single source of truth. Nothing drifts, because nothing is typed twice. This page is built the same way — the file you are reading is generated, and the build refuses to write it if any of its own checks fail.

    14The questions I actually get

    Fair questions, answered plainly.

    “Won’t AI just do all of this by itself in a year?”
    The drafting, probably — it already does, and I use it for exactly that. The deciding, no. Every system here is built on the assumption that the model is a fast, capable writer with no judgment and no stake in your reputation. So the machine does the watching, the arithmetic and the drafting, and a human does the one thing that carries consequences: approving. If a model gets good enough to replace that, you’d still want a gate in front of it. The gate is the product. The rest is wiring.
    “Why should I trust you with my data?”
    Start by not giving me any. The four tools on this page run entirely inside your browser — there’s no server for them to send your file to. Open the network tab and check; after the page loads it makes zero requests. That’s the design, not a promise. When we do work together, the same posture holds: everything is built in your accounts, the sensors are read-only so nothing writes back to your source data, and every run logs what it touched.
    “Do you actually have customers?”
    No. Not yet — I’ll say that plainly rather than let a stock photo imply otherwise. Automated Workflow is new, I’ve built everything you see here myself, and you’d be first. What that buys you: my full attention, pricing set to earn a review rather than pad an invoice, and a founder who cannot afford to do a mediocre job. What it costs you: you can’t call a reference. So judge the work instead — that’s why it’s all pressable, readable, and free to inspect.
    “My spreadsheet is a disaster. I’m embarrassed to send it.”

And every run is logged, so when something looks off there’s a row explaining what it read and what it did. When I do get something wrong, it goes on the build log.
